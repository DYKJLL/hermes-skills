# 技能流程

## 触发时机

**第一层触发时机**：执行以下命令后立即激活，不等用户问
- 安装技能 / 更新技能 / 升级技能命令
- 手动修改 SKILL.md

**第二层触发时机**：beta状态稳定后，找时间单独跑

## 【第二层】上线前验证

| 技能类型 | 验证要求 |
|---------|---------|
| 自建技能（我们原创） | 完整6步 + 三轮回验 |
| 改编技能（拿别人技能改成我们的） | 完整6步 + 三轮回验 |
| 第三方技能（直接安装拿来用） | 能用 + 稳定 + 配置成功 → production-ready |

### 6步标准流程（自建/改编）

```
第1步 测试     → 实际运行核心功能
第2步 审核     → 代码/逻辑审查
第3步 审核2    → 换个角度再审查
第4步 可靠性   → 断网/超时/空内容/异常输入
第5步 稳定性   → 多次运行是否稳定
第6步 三轮回验 → 完整循环 × 3 → production-ready
```

### 三轮回验操作规范
- 每次完整执行核心功能路径
- 记录输出结果
- 3遍全部通过 → production-ready
- 未跑完 → beta，不能进正式流程

### 第三方技能验证清单
- [ ] 能用：核心功能正常运行
- [ ] 稳定：多次调用无异常
- [ ] 配置成功：参数/凭证/权限到位

## 状态流转

```
安装/更新/升级命令
        │
        ▼
   第一层触发（5步验证）
        │
        ▼
   beta（能用，待验证）
        │
        ├── 第三方 → 能用+稳定+配置成功 → production-ready
        │
        └── 自建/改编 → 完整6步+三轮回验 → production-ready
```

---

## 约束规则（一级准则）

hermes-dojo / 训练道场 / skill-factory 等系统机制有创建、迭代、更新、合并技能意图时，必须通知用户确认，不能直接执行。

通知时机三选一：
- 系统重启时
- 准备安装/更新技能时
- 正常使用中发现系统有相关意图时

对用户让我安装的技能、用户自己创建的技能不适用。
